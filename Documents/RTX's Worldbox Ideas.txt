HOW I WORK (rules for myself)
-----------------------------
1. FLESH OUT BEFORE ADDING. A feature isn't done until it has: a clear purpose, a clear way to get it, real effects, interactions, an icon/text/visual, balance and testing. No more half-built features. (ShinobiBox taught me this.)
2. ONE PROJECT AT A TIME. One "active" mod, everything else waits.
3. NO DEADLINES TO THE PUBLIC. Share progress, not dates.
4. SMALL RELEASES. Ship small finished things often.
5. OPUS AS A BUILDER AND TEACHER. Watching Opus build my dream mods is motivating and teaches me how things work in WorldBox. That is a fine way to learn IF I also: read what it wrote, ask it to explain files I don't understand, and make small edits myself. Goal: I understand every file I ship.
6. LIBRARIES FOLLOW REAL NEEDS. Only put something in a library mod if two or more mods need it.

LIBRARIES
---------
PossessLib - player-facing layer: possession controls, inventory, equipment, crafting, key bindings, HUD, API for other mods.
  - Old notes still relevant: view a unit's inventory from its window without possessing, coins slot, eating, gathering, level-up indicator, armor stat readout.
  - Old bug to check: a "cursed" weapon stays equipped no matter which hotbar slot is selected.
  - Ask Opus for a direction review: what's solid, what's fragile, ranked roadmap, shippable v1.0.

Visible Armors - armor drawn on units. Ideas from old notes: set bonuses (3 matching pieces give a status bonus), easy for other mods to register their own armor looks, default to normal look when art is missing, community vanities (custom accessories overlaid on units) later.

EffectsLib (IDEA) - helps modders add things around or on a unit (Stands, armor/accessory effects, summons, pets).
  - Statuses are a good foundation (StatusAsset supports sprites with offset, scale, rotation, animation, light glow, override callbacks, periodic actions, stat changes, duration, saving, UI icons).
  - Two layers: (1) status-based effects (auras, glows, orbiting things, buffs); (2) companion entities (Stands, summons, pets with their own movement/attack).
  - Don't build it first. Build the first Stand or accessory effect, then pull out what is reusable.
  - Open question: mainly visual, or does it also handle summon behaviour?

NML Workshop Mod Browser - in-game Workshop browser for NeoModLoader, like tModLoader.
  - NML already has: ModWorkshopService (+Windows/Unix backends), a subscribed-only list window, upload windows. Tags: "Mod", "Unverified Mod", "Mod Loader".
  - Needs: browse ALL Workshop mods, search/sort/filter, install, update, enable/disable, "Download All" (installed but left disabled for safety), dependency handling.
  - Game uses Facepunch.Steamworks, AppID 1206560.

WORKING WITH OPUS (TIPS)
------------------------
- Small/clear tasks: talk to Opus directly.
- Big/vague tasks: give the goal, where the files are, what "done" looks like, and ask it to say what it could not verify.
- After a mod is built, keep iterating in the SAME session. Paste screenshots and log errors.
- New session: tell it to read docs/DESIGN.md and the mod folder first.
- Keep a backup (copy the folder or use git) before big changes. Close WorldBox before builds.
- To learn: ask Opus to walk through each file it wrote, then change one small thing by hand each session.
